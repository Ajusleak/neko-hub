## Purpose

This repository is the governed engineering knowledge base for NEIKOS HUB. It contains architecture, specifications, engineering standards, operational guidance, and release documentation.

The repository is governed by **NEOS — NEIKOS Engineering Operating System**.

NEOS governs how the repository is operated. NEIKOS HUB specifications define the product and platform engineering system.

---

## Operating Principles

1. Governance before implementation.
2. Discovery before change.
3. Single source of truth.
4. Inheritance over duplication.
5. Explicit dependencies.
6. Traceable decisions.
7. Validation before approval.
8. Baseline before expansion.
9. Architecture before implementation detail.
10. Documentation is an engineering artifact.

## Engineering Lifecycle

```text
Proposal
  ↓
Planning
  ↓
Repository Discovery
  ↓
Authoring / Implementation
  ↓
Technical Review
  ↓
Architecture Review (when applicable)
  ↓
Consistency Validation
  ↓
Approval
  ↓
Baseline Freeze
  ↓
Release Publication
```

A change is not considered complete merely because implementation exists.

---

## Repository Discovery

Before a material change, establish:

- current baseline;
- governing documents;
- authoritative specifications;
- affected systems and documents;
- dependencies and dependents;
- validation requirements;
- risks; and
- assumptions.

See `AGENTS.md` for the mandatory AI discovery procedure.

---

## Validation

Applicable changes must pass:

1. Discovery validation
2. Technical validation
3. Documentation validation
4. Consistency validation
5. Review readiness

Draft, reviewed, approved, and baselined states must never be represented as interchangeable.

AI agents are governed engineering participants.

## Baseline Policy

A baseline is an explicitly reviewed and approved repository state.

A baseline identifies:

- version;
- included artifacts;
- validation status;
- approval status;
- known exceptions; and
- effective state.

Changes after a baseline belong to a subsequent governed release unless explicitly classified as an approved correction.

---

## Definition of Done

Repository work is complete only when:

- the objective is satisfied;
- applicable governance has been followed;
- dependencies and impacts are assessed;
- documentation is synchronized;
- validation requirements pass;
- required reviews are complete; and
- the resulting state is accurately identified as draft, reviewed, approved, or baselined.
